# 本地科研智能体架构规范

开发以本地单用户、单机运行作为验收环境。禁止过度设计，禁止为假想需求添加防御性措施。扩展功能在出现实际需求时实现。

本文负责设计边界、目标流程与验收标准；已实现能力、待实现部分和验证限制统一见 [STATUS.md](STATUS.md)，不要将目标流程视为实现清单。

## 1. 运行与目录

| 目录 | 首版职责 |
|---|---|
| `apps/web/` | Next.js + TypeScript。展示项目、对话、文献、任务进度、报告和原文定位。 |
| `apps/api/` | FastAPI。处理本地请求，读写 SQLite，提供文件和报告。 |
| `apps/worker/` | 单个 Python 进程，顺序领取和执行任务。与 API 共用后端依赖。 |
| `src/agents/` | Agent 工作流。`literature.py` 使用 LangGraph 表达科研问答分支、补检、综合与核验。 |
| `src/tools/` | 显式注册、发现与调用可复用工具，校验参数并执行项目和来源范围约束；能力独立于 LangGraph。 |
| `src/integrations/` | 外部服务协议适配：OpenAlex、模型与网页搜索。 |
| `src/literature/` | 文献业务。`retrieval.py` 负责检索排名及收藏夹候选，`evidence.py` 负责 PDF、摘要和网页片段取证。 |
| `src/persistence/` | `storage.py` 管理 SQLite 和数据路径，`repository.py` 管理持久化与事务。 |
| `src/infrastructure/` | `settings.py` 管理本机配置及环境变量，`logging_setup.py` 管理日志脱敏与轮转。 |
| `src/prompts/` | 集中存放 Markdown 提示词，保留 `literature/` 与 `runtime/` 分类。 |
| `data/` | 保存 research.db、原始文献和导出报告；加入 Git 忽略。 |

后端用 uv、前端用 pnpm，提交各自锁文件。直接在本机启动前端、API 和 worker。前端和 API 默认只监听回环地址。数据库随应用初始化，无需安装数据库服务、Docker 或 Conda。OpenAlex 和 OpenAI 兼容模型设置可保存在 `TUFA_DATA_DIR` 的 SQLite 中，环境变量优先；密钥不在接口响应或日志中回显。LangGraph 问答通过模型集成层生成回答并保存证据。

## 2. 存储与后台任务

API 和 worker 连接同一个本机 SQLite 文件，启用 WAL，每个连接开启外键。数据库写入使用短事务；联网、模型推理和 PDF 解析在事务外执行。

- 项目保存对话、文献和报告。项目内跨对话共用材料。以普通主键关联记录，不生成身份令牌、会话令牌、任务令牌或租约令牌。
- 文献按 DOI 或 arXiv ID 识别。上传文件时可按内容摘要识别相同字节；原文变更时保存新版本。证据记录引用原文版本、页码、段落或表格行列。
- 任务表记录输入、状态、当前阶段、结果和错误。API 插入待处理任务并返回 ID；单 worker 领取后更新为执行中，完成后写入结果。前端轮询任务详情。worker 重启时将上次中断的任务标为中断，由用户点击重新执行。
- 报告版本保存正文、证据引用及父版本。新报告与任务成功状态在同一事务中提交。修订产生新版本，旧报告仍能打开。
- 首版不设置账户、角色权限、鉴权中间件、分布式队列、心跳续租、幂等键、事件重放或 token 预算账本。保留直接影响科研结果的检查，如证据定位有效、数值单位一致。

以下核心工作流为架构目标；各步骤的实现范围以项目状态和代码为准。

收藏夹问答在任务提交时保存成员快照，只检索项目内快照文献，不读取其他对话历史或调用外部检索；空集合返回证据不足。普通混合来源检索遇 OpenAlex 故障时保留本地结果并提示不完整。

## 3. 核心工作流

### 工具与编排边界

`src/tools/` 通过 `ToolRegistry` 暴露论文检索、网页搜索和证据提取。每个工具声明名称、说明与 JSON 输入结构，可以由普通 Python 调用方按名称执行，无需构造图状态或创建后台任务。API 搜索、worker 检索任务与科研图节点使用同一工具入口。使用方式及扩展契约见 [工具说明](../src/tools/README.md)。

`ToolContext` 保存调用方确定的项目、来源与收藏夹论文快照；调用参数只描述本次操作，不能覆盖这些范围。目录发现和执行均检查工具是否适用于上下文。收藏夹检索与取证始终使用快照和项目文献的交集；本地原文路径来自仓储，工具不接受任意文件路径。

`tools/search.py` 和 `tools/read_paper.py` 负责工具契约与适配，单次检索和取证分别委托给 `literature/retrieval.py`、`literature/evidence.py`，外部协议复用 `integrations/`。文献业务不依赖工具注册器或 Agent 状态。`agents/literature.py` 继续负责规划、补检次数、阶段、综合与核验；worker 与 `persistence/repository.py` 负责任务及结果提交。配置与日志统一复用 `infrastructure/`。工具目录不做任务调度，也不自动让模型选择工具；模型自主调用循环需另行设计与验收。

模块路径以 `src` 为包根，应用、脚本和测试直接导入新位置，不保留旧路径转发模块。提示词按集成文件位置定位到 `src/prompts/`，数据路径由 `persistence/storage.py` 定位到仓库根目录；移动 Python 文件不能把默认数据目录变为 `src/data/`。

### 科研流程目标

1. **路由。** 明确的界面操作直接执行；自然语言请求按意图进入论文检索、综述生成或报告修订。查询已有材料直接读库。
2. **检索。** 用研究问题生成子问题和检索式，从 OpenAlex 和项目文献收集候选。关键词检索使用 SQLite FTS5/BM25；嵌入以 float32 BLOB 存储并记录模型和维度，使用 NumPy 对候选集算余弦相似度。两路按 RRF 合并，取前 20 篇重排、最多精读 6 篇（每个子问题）。高相关种子可扩展一跳引用。
3. **取证。** 从正文和实验表抽取方法、基线、数据集、指标、数值、单位与限制，保存原文锚点。只有摘要时标明来源层级，缺失字段留空。
4. **补检。** 缺相关研究时改写外部查询；已找到论文但缺对照细节时查表格和附录。额外检索最多两轮，无新增证据则停止。
5. **写作与核验。** 逐条关联结论与证据，核对数值和比较条件。仅有准确率证据时不得声称降低成本。输出中文综述和 CSV 证据表，点击引用能打开对应原文。
6. **修订。** 读取指定报告和新增论文或筛选条件，更新受影响结论，展示变化及其依据。

## 4. 提示词

网页搜索为显式 `web` 来源，配置、协议与证据边界见 [WEB_SEARCH.md](WEB_SEARCH.md)。搜索服务结果经统一集成函数进入有限补检流程，保存 URL、获取时间、引擎及摘要/正文层级；不写入论文库，不改变收藏夹隔离或 `all` 的文献范围。模型只读取作为数据传入的网页文本。

提示词写作与加载契约见 [PROMPTS.md](PROMPTS.md)。每个已接入模板以 `CURRENT_TIME` 占位符开头，统一调用入口逐次注入带 UTC+08:00 偏移的北京时间后作为 system 消息发送；业务输入单独作为 user JSON，不参与模板求值。

主控目标模板为 `src/prompts/runtime/route.md`。科研节点使用 `src/prompts/literature/` 下的 plan_review、rewrite_query、screen_paper、extract_evidence、assess_gap、synthesize、verify_claim、revise 等同名 Markdown 文件；实现对应节点时创建。统一模型调用函数按 ID（如 `literature/plan_review`）加载文件，代码传入结构化数据并用 Pydantic 校验输出。提示词正文不得散落在代码中。用 Git 跟踪修改；用固定输入检查调词后的输出行为。首版不建设提示词快照仓库，不要求逐调用计算哈希。

## 5. 本地接口与验收

API 提供项目和对话创建、项目文献导入和列表、任务提交和状态查询、证据定位、报告版本读取与修订。任务提交返回 run_id，任务详情含当前阶段与结果或错误。修订请求传入基础报告版本 ID。

1. **脚手架。** 在空数据目录启动前端、API、worker，验证首页、健康检查、SQLite 初始化及 FTS5 可用，在 README 记录实测命令。本阶段不实现科研流程。
2. **检索。** 用固定问题检索论文，检查已知相关论文能否找到，记录排名。验证相同文件重复导入后的文献列表。
3. **综述。** 从一条数值结论点到正确的原文表格。用缺失成本数据的例子验证系统能够输出证据不足。
4. **修订。** 在另一个对话中新增论文，更新旧综述，检查新旧版本与引用。比赛评测使用固定题集对比单轮向量检索、混合检索和完整工作流的召回、引用支持率、问题覆盖和耗时。
