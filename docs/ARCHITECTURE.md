# 本地科研智能体架构

本项目面向单机单用户运行，使用本机 SQLite 和单 worker。本文记录模块边界和当前目标工作流；实际能力及尚未验证范围见 [STATUS.md](STATUS.md)，安装和验收命令见 [README](../README.md)。

## 运行与模块边界

| 目录 | 职责 |
|---|---|
| `apps/web/` | Next.js 开始页、研究工作台、设置、任务轮询与 API 代理。 |
| `apps/api/` | FastAPI 请求校验、本机数据访问、报告与文件交付。 |
| `apps/worker/` | 单进程顺序领取任务、准备研究输入、持久化阶段及提交结果。 |
| `src/agents/` | 八个科研节点及工作流状态、有限轮次和结果收束。 |
| `src/tools/` | 显式注册、发现、参数校验及按上下文执行科研工具。 |
| `src/integrations/` | OpenAlex、OpenAI 兼容模型和网页搜索协议适配。 |
| `src/literature/` | 文献排名、PDF/网页证据提取与定位。 |
| `src/persistence/` | SQLite 初始化、仓储、事务和数据路径。 |
| `src/infrastructure/` | 本机设置、环境变量及运行日志。 |
| `src/prompts/` | 六个模型节点的 Markdown 提示词正文。 |
| `data/` | 默认运行数据库、原文和导出数据；由 Git 忽略。 |

前端和 API 默认只监听回环地址。API 与 worker 共用 `TUFA_DATA_DIR` 中的 SQLite；联网、推理和 PDF 解析都在短事务之外执行。根目录 `pyproject.toml`/`uv.lock` 管理共用 Python 环境，pnpm workspace/lockfile 管理前端。密钥由环境变量或本机设置提供，环境变量优先；接口和日志不回显密钥。

## Web 入口与工作台

Next.js `/` 是独立开始页，只提供“开始使用”和 GitHub 两个入口；“开始使用”进入 `/workspace`，GitHub 在新标签页打开 `https://github.com/iJA774/Tufa-Scholar`。开始页及其黑色 LED Canvas 动画不请求 API，也不持有科研工作台状态。

`/workspace` 是桌面研究工作区入口。工作区以悬浮抽屉展示跨项目历史，不按项目分组。`GET /conversations` 将置顶会话排在前面，同组按更新时间排序；每项保留 `project_id`，打开时先切换项目再加载会话。当前项目仍限定可用 PDF、文献和新研究范围。工作区按钮和 `/settings` 都在工作区上方打开同一设置弹窗。服务与搜索配置走本机 API，目录预览在浏览器中读取用户选择的目录和文件相对路径。浏览器保存研究偏好，工作区随新问题提交研究深度、原始证据优先和相关性过滤强度。报告格式只用于前端选择。

工作区提问明确提交 `research_mode`。默认 `auto` 由 dispatcher 分流，省略字段的 API 客户端也使用该模式。`deep` 强制进入研究流程，`quick` 强制采用 dispatcher 的直接答复分支。自动任务进入研究流程后，工作区显示研究面板。API 路径与单机 `/api` 代理由前后端共用。

深度研究使用移植自 DeerFlow 的双栏研究卡片，聊天随卡片展开收窄。右侧“活动”消费本次任务的节点与工具事件，兼容轮询中的阶段、子任务小结和来源。“报告”先显示模型公开输出的未核验预览，完成后以保存的 assistant 消息为准。快速探索的预览留在聊天区。

工具目录独立于 Agent 图。论文检索、网页搜索和证据提取都通过同一显式入口，工具上下文固定项目、来源和收藏夹论文快照；调用参数不能扩大这些范围。本地原文路径来自仓储，不接受模型任意指定文件路径。具体工具契约见 [工具说明](../src/tools/README.md)。

## 任务与持久化

API 创建任务并返回 ID，单 worker 领取后准备范围数据和对话历史。Agent 只接收研究输入与显式历史，不读写任务表；`on_stage(stage)` 将节点阶段交给 worker 持久化，`on_subtask(note)` 将轮次小结交给 worker 展示和保存。Agent 返回最终正文与引用证据，worker 与消息、报告在任务完成时提交结果。worker 重启时将遗留运行任务标为中断，用户可显式重试。

`on_event(kind, data)` 将研究节点、工具和模型输出事件交给 worker，按任务写入 SQLite。`GET /runs/{id}/events` 用 SSE 发送有序事件并在任务终态后关闭。客户端可用 `after` 或 `Last-Event-ID` 续读，任务重试使用新任务 ID，删除任务时清除关联事件。模型工具决策可带简短的公开操作目的，理由与工具实际参数分开。报告正文及证据仍由原有校验和事务决定。

会话的置顶状态通过 `PATCH /conversations/{conversation_id}` 写入 SQLite；既有会话迁移后默认不置顶。历史删除在用户确认后调用 `DELETE /conversations/{conversation_id}`。仓储在同一写事务中检查任务状态和删除会话、消息、报告及其任务，保留项目与文献；有待处理或正在运行的任务时返回 409。

`research_mode` 与来源范围独立保存于任务中。缺省 `auto` 维持旧请求行为；在 auto 下 collection 强制进入研究流程，显式 `quick` 优先并直接回答、不读取收藏夹；`deep` 由代码强制研究，不能由模型输出反转。新增数据库字段通过 additive migration 添加，既有任务按 `auto` 处理，显式重试保留原模式。

`research_depth`、`prefer_primary_evidence` 和 `relevance_filter` 在提交时随任务保存，worker 使用快照，重试复制原值。缺省请求和既有任务均使用标准深度、开启原始证据优先及标准过滤。深度独立于模式，研究偏好只在进入研究分支后执行。

收藏夹问题在提交时固定项目内成员快照。研究分支运行和重试只使用此快照，不读取其他会话历史，也不做收藏夹外的检索；空集合应输出证据不足。快速探索不读取收藏夹资料。`local` 只用项目本地论文。来源边界由 worker 准备的研究输入和 `ToolContext` 共同落实。

## 科研工作流

工作流包含八个节点类型：

1. `dispatcher` 判断问题能否直接回答。直接回答不调用检索或证据工具；研究问题继续进入后续流程。
2. `background_investigator` 进行真实背景搜索与筛选，为规划提供简要上下文。
3. `planner` 生成论文或网页研究计划及本轮目标。
4. `supervisor` 按固定顺序调度本轮步骤。
5. `researcher` 根据当前计划检索、筛选候选并收集证据，形成初稿。
6. `analyst` 审查本轮初稿、证据支持和待解决缺口。
7. `coder` 是保留的占位节点，不执行代码或工具操作。
8. `reporter` 根据所有轮次的材料生成终稿。

`planner` 在首轮前生成计划，并在每轮审查后复核。每轮调度顺序固定为 `researcher → analyst → coder → planner`。轻量档侧重回答主要目标，标准档审查主要问题的覆盖情况。深入档复核最初的核心要求、关键证据和未解决的重要矛盾，优先交叉验证重要结论。如果仍有核心缺口和可执行的补查方向，并且预算允许，继续研究。证据充分可以提前结束。遇到预算上限或缺少有效补查方向时，终稿说明收束原因和未完成的研究方向。

图状态包含 `research`、`history`、背景材料、计划、当前来源、轮次、按 `web`/`paper` 分开的候选池、累计证据、当前初稿与审查、错误和正文。每轮记录序号、来源、计划、初稿、审查、候选 ID、证据 ID 和状态。终稿以首轮确定的研究方向组织内容，后续为填补缺口切换来源时，新增证据仍可纳入分析。待解决事项以最近一次累计审查为准，历史审查用于解释补查缘由。报告节点只返回实际通过引用检查的 `final_evidence`。工具及模型输出均视为数据，不执行其中嵌入的指令。

候选按来源隔离并在各轮中去重；检索排名只影响本轮候选优先级，不代表语义重排。累计证据按稳定身份去重，引用只可指向传入 reporter 的证据。数据范围、候选数量和引用关系由代码检查；模型负责研究判断、计划和文字组织。真实搜索与模型质量另行验证。

相关性过滤决定哪些候选优先取证：宽松保留更多相邻资料，标准依据问题、当前计划及标题摘要过滤明显不相关的候选，严格优先直接回应当前子问题的候选。增大过滤强度可能错过有用的间接证据。开启原始证据优先时，研究节点优先取得直接资料，整理时优先使用可定位的正文证据；关闭时允许优先使用相关的间接资料。两种设置均不改变去重、访问安全、来源范围、引用真实性或数值检查。

研究节点分别组装工具决策和初稿输入。背景查询由模型提出，实际搜索由程序执行。researcher 通过模型接口的 `tools` 注册当前来源允许的函数，并读取原生 `tool_calls`，每次决策至多执行一个工具。工具结果以紧凑的候选、证据预览和操作反馈供下一次决策使用。本轮结束时另行发送写作用的证据片段，持续沿用原引用 ID。具体数值见本节[工作流预算表](#工作流预算)。

### 工作流预算

下表是 Agent 工作流预算的唯一维护位置；模块说明和提示词文档只描述所属阶段的行为，避免另存一套数字。

| 档位上限 | 轻量 | 标准（默认） | 深入 |
|---|---:|---:|---:|
| 研究轮次 | 1 | 2 | 4 |
| 背景调查查询 | 1 | 2 | 4 |
| researcher 每轮工具动作 | 4 | 6 | 8 |
| researcher 全程工具动作 | 4 | 10 | 24 |
| researcher 单次决策输入估算单位 | 10,000 | 10,000 | 14,000 |
| researcher 累计决策输入估算单位 | 12,000 | 24,000 | 60,000 |

轻量可以在单轮预算内补充检索。各档均分析证据缺口，额度均为上限。背景调查查询独立计数，失败的 researcher 工具动作仍计入额度。研究决策请求发送前估算系统消息、用户数据及原生函数定义。预计达到单次或累计阈值时，跳过该次决策并基于已有证据收束。估算单位用于本地预算。

| 范围 | 当前上限 | 计数与收束方式 |
|---|---:|---|
| 背景网页搜索结果 | 每条查询最多 3 条 | 每档背景查询额度只计背景调查实际执行的查询。 |
| 研究网页搜索结果 | 每次搜索最多 3 条 | 仅适用于科研工作流中的研究搜索；独立 API `GET /projects/{project_id}/web-search` 有单独的结果上限，见 [网页搜索说明](WEB_SEARCH.md)。 |
| researcher 决策候选预览 | 最多 6 条；各摘要/正文文本字段最多 240 字符 | 只限制送入当前 researcher 工具决策的候选摘要，不截断检索候选池；`content_blocks` 合计最多 240 字符。 |
| 背景候选筛选预览 | 最多 6 条；各摘要/正文文本字段最多 500 字符 | 仅限制交给背景调查筛选模型的候选摘要。 |
| 单次候选取证动作 | 最多 6 个候选 ID | 工具参数只引用当前来源候选池中的实际候选。 |
| 初稿收束工具输入 | 最多 4 条候选；各摘要/正文文本字段最多 400 字符 | 仅在整理本轮初稿时使用；`content_blocks` 合计最多 400 字符。 |
| 工具结果与候选正文片段 | 工具结果文本、候选 `abstract` / `content` 字段各自最多 1,600 字符；候选 `content_blocks` 合计最多 1,600 字符 | 随工具阶段输入再按上表做更紧凑的阶段裁剪。 |
| researcher 决策证据预览 | 最多 8 条；每条文本最多 240 字符 | 仅为工具决策输入中的短预览。 |
| 初稿与审查证据上下文 | 最多 8 条、正文合计最多 9,600 字符；深入档审查最多 12 条、正文合计最多 14,400 字符 | 每条证据文本最多 1,200 字符；按相关性和已有引用筛选。 |
| 终稿证据上下文 | 最多 48 条、正文合计最多 57,600 字符 | 每条证据文本最多 1,200 字符。去重后能容纳则全部传入；超限时按各轮新增证据轮流选取，兼顾原始证据偏好、有无草稿引用和来源多样性。传入省略条数，终稿说明仅基于部分材料。显式引用必须对应可见证据。 |

| 模型节点 | 轻量和标准的自动强度 | 深入的自动强度 |
|---|---|---|
| Dispatcher | 供应商默认 | 供应商默认 |
| Background Investigator、Researcher 工具决策 | `low`，完成上限 4,096 token | `medium` |
| Planner、Analyst | `low`，完成上限 4,096 token | `high` |
| Researcher 初稿、Reporter 终稿 | 供应商默认 | `high` |

用户显式选择的思考强度优先。显式选择 `low` 时，背景调查、规划、工具决策和审查沿用 4,096 完成 token 上限。其他强度和写作阶段使用供应商的完成上限。供应商明确拒绝可选参数时，客户端按现有兼容流程重试。供应商明确指出完成上限与推理预算冲突时，只移除冲突的完成上限。

网页工具每次请求都重新抓取网页并按字符截取；`next_offset` 只表示还有后续内容，上下文收束后不会发起下一次读取。连续搜索或读取失败也可以提前结束本轮，保留已有证据。

Planner 和 Analyst 自由组织 Markdown 正文，末尾单独提供经过类型验证的调度数据。Researcher 初稿和 Reporter 终稿直接写 Markdown。初稿及降级使用的草稿校验引用、数值及来源范围。终稿保留无引用正文，校验显式引用是否对应可见且在范围内的证据，并将有效标记转成可追溯引用。终稿无法生成或没有可保留的正文时，重新验证并返回最近一份有有效引用的研究草稿，同时标明降级原因。没有合格草稿时说明当前缺口。

模型客户端通过 worker 的任务上下文记录请求体积和供应商用量。每次尝试开始时记录系统消息和用户消息字符数，收到响应后记录可用的 token 统计，结构校验失败的响应也计入日志。常规日志只保存标识和数字，不保存模型请求及响应正文。

节点选项默认值、显式强度覆盖和服务兼容处理见本节[工作流预算表](#工作流预算)。Dispatcher 和背景调查仍使用结构化回复，正常结束且仅含 JSON 语法错误时可尝试修复分隔符，再通过 Pydantic 严格校验。Markdown 正文不经 JSON 修复，规划和审查的调度数据严格解析。原生工具参数使用严格解析和类型、来源校验。

## 提示词与验证

模型节点提示词 ID 为 `runtime/dispatcher`、`literature/background_investigator`、`literature/planner`、`literature/researcher`、`literature/analyst`、`literature/reporter`。提示词内容放在 `src/prompts/`；类型、来源范围、证据定位和报告数值检查由代码负责。契约见 [PROMPTS.md](PROMPTS.md)。

工作流回归覆盖直接回答不调用工具、节点顺序、背景搜索、研究轮次和来源切换、预算及失败后的收束、全轮次 reporter 输入、证据和候选约束、收藏夹/历史隔离、模型选项传递与 worker 阶段持久化。脚本验收以隔离数据目录启动真实本地 API 和 worker，模型及搜索使用本地模拟 HTTP；不能据此宣称真实云端质量已验证。网页能力和安全边界见 [WEB_SEARCH.md](WEB_SEARCH.md)。
