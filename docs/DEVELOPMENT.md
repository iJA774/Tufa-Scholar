# 设计取舍与技术债

本文记录维护代码时需要知道的设计选择。当前能力见 [项目状态](STATUS.md)，节点、接口和预算见 [架构文档](ARCHITECTURE.md)，命令见 [README](../README.md#验证)。

## Windows 启动器命令解析

本机安装与启动配置使用根目录锁文件及已有启动入口。PATH 中可能同时存在用户安装的 pnpm 和工具运行时提供的 pnpm；启动器解析 uv、pnpm 时只选取按 PATH 顺序匹配的第一个程序，避免把多个路径拼成无效命令。不通过删除系统 PATH 条目或硬编码本机安装路径解决，以保留正常的程序优先级和安装可移植性。

## 历史问题重新回答

报告降级也可能以成功状态保存，因此不能只依赖失败任务的重试入口。原问题下方新增“重新回答”，使用当前模型设置创建新任务，并保留原来源范围、收藏夹快照和研究偏好。现有重试接口继续保留原模型快照，避免改变其恢复语义。

重新回答不复制用户消息、不覆盖旧报告。沿用原始任务的历史边界，同时排除该问题的旧回答和后续轮次，避免降级内容影响再次作答。仓储在同一写事务内检查会话中的活动任务并入队，防止重复点击产生并行回答。不采用复制输入框再发送的方案，以保留已删除收藏夹的原成员快照。

## 本地文档离线转换

设置使用固定原文目录，用户可在资源管理器中放入文件并显式启动批量转换。服务端直接读取目录，省去浏览器选择和上传步骤。转换状态独立保存在同一 SQLite 的 `conversion_batches`。API 内单协调线程顺序启动可终止的解析子进程，继续使用现有的文件大小、时间和进程内存预算。

采用 MIT 许可的 pdfplumber、python-docx 与已有 charset-normalizer；在 Python 3.13 / Windows 环境安装锁定依赖。pdfplumber 可访问字位置、字号和表格；python-docx 支持段落与表格的源顺序。未采用 PyMuPDF（AGPL/商业授权取舍），也未引入多格式框架、Office 自动化、模型或 OCR 服务。布局启发式不能保证所有论文的阅读顺序，局限随结果交付。

PDF 转换文本与原页缓存一起复用现有 PDF 版本和项目 FTS，原始字节哈希防止重复论文，已存在版本不改写证据。DOCX、TXT 暂不导入：当前论文原文交付固定为 PDF，普通笔记也不一定具有论文语义。后续应增设独立 `local_documents`、`document_versions`、`document_segments` 及显式文档工具，以项目关联、原始哈希、转换参数/版本、页码或段落定位接入候选和证据；不要复用 PDF 文件接口、伪造页码或改变既有证据 ID。此为后续扩展方案，尚未实现。

结果保留供下载，输入副本按任务生命周期清理。固定目录转换按同名 Markdown 跳过，文件内容变化后仍按同名处理，重新转换需先移走已有结果。原始 PDF 的文献版本仍按字节哈希关联。

## 本地文档分析与分类

分类沿用文档批次的进度和取消机制，在科研图之外按文件执行。独立入口允许对已有 Markdown 补做分类，启动转换仍只运行本机解析器。SQLite 将多领域和主题标签分别关联到文档，以便从任意一个领域找到跨学科资料。内容哈希用于调用模型前查重，改名或复制的相同内容复用分类。模型输出通过结构校验后才写入分类关系。

## 提问框来源开关

“网络搜索”和“本地文献”随任务保存，使排队、重试和重新回答都使用提问提交时的来源范围。缺省开启两项以兼容旧请求。开关在工作流和工具执行边界约束检索，避免仅靠按钮状态或提示词来限制来源。

模式按钮与来源开关共用字号、内边距和图标间距。来源开关的悬停样式保留亮灭差异，启用减少动态效果时即时切换。

## 本机 SQLite 与单 worker

项目面向单用户，SQLite 同时保存任务、对话、证据和报告，单 worker 顺序领取任务。这个组合便于本机安装，也让终稿、证据和任务完成状态能在同一事务里提交。搜索、推理和 PDF 解析在事务之外运行。

分布式队列或多 worker 需要处理租约、重复执行、任务恢复和资源竞争，目前单用户使用范围无需承担这些成本。worker 重启后，遗留的运行任务标为中断，由用户主动重试。

## 研究预算与证据收束

工具决策只携带当前候选预览、证据预览和近期反馈。初稿再读取筛选后的证据，终稿继续使用稳定的引用 ID。这比每次把历史轮次与全文传给决策模型更节省输入，也保留了引用和数值核验所需的原始片段。

简单截短单次消息无法阻止模型持续调用工具。工作流同时限制调用次数和累计输入，预算耗尽后关闭工具阶段，使用已有证据成稿。上下文预算采用本地估算，便于跨供应商使用。各模型的实际分词、账单和长问题下的质量差异仍需要真实服务数据。

研究深度用离散档位设置轮次、工具动作、背景查询、输入预算和默认节点思考强度。深入档把更多推理资源用在问题拆解、取证和审查，并以覆盖要求、关键证据和重要矛盾判断能否提前收束。继续补查需要有实际可执行的新方向，以减少相似查询反复消耗预算。浏览器保存选择，逐任务持久化快照，重试使用已保存的档位和显式思考强度。

相关性过滤沿用本机词项评分，并加入本轮计划作为比较条件。它不需要额外模型调用，但无法判断所有同义、跨语言或间接关联；严格档可能降低覆盖。证据优先级只影响选材，不改变报告校验。

终稿单独分配证据额度。优先传入完整的去重证据池；超出额度时，让各轮新增材料轮流进入，避免首轮引用较多就占满终稿输入。选材兼顾原始证据偏好和来源多样性，具体论证价值仍由 Reporter 对照问题和证据判断。没有采用词项分数选终稿材料，也没有为排序增加模型请求；超限时仍可能遗漏有用的片段。

## 原生工具调用与活动记录

模型通过 Chat Completions 的原生 Function Calling 返回工具请求。应用掌握可用工具、参数、来源、分页和预算，并把简短的公开操作目的独立送到活动面板。旧做法要求模型在普通答复中拼装工具调用对象，容易出现格式错误，还会重复传入工具定义。

工作流以紧凑状态传递最近的工具结果。完整回放供应商工具消息会增加请求体积，应用仍需校验权限与证据。原生调用能力及供应商兼容性需要按实际模型验证。

工具参数被拒绝时，worker 记录任务、调用、工具、来源、错误码和安全的字段路径。涉及候选池时，日志记录参数形态、候选池大小和有限数量的内部候选 ID，其他参数值经过省略或脱敏。

活动事件按任务保存在 SQLite，前端通过 SSE 按游标续读。单靠轮询阶段只能知道当前节点，无法还原此前的工具操作或流式输出。轮询继续提供任务结果和阶段小结，也能覆盖缺少活动事件的历史任务。

活动详情的展开状态由研究面板管理。完成或失败的活动默认收起详情，可手动查看检索词、来源、操作理由或错误信息。

活动图标播放仓库内的动画素材，进行中循环播放，完成或失败后分别停在对勾或警告画面。标题扫光仅在活动进行时启用。系统启用减少动态效果时，图标使用静态画面，标题使用实色。

提问框默认使用自动判断，复用已有的 dispatcher 分流。研究面板根据任务的研究阶段或活动记录展开，避免在分流前打开，也避免用户手动关闭后被同一任务的后续阶段重新打开。

## 工作台提问框动效

研究模式菜单位于触发按钮下方。起始页允许菜单覆盖预设问题，避免展开时推挤卡片；已有对话时临时给菜单留出底部空间，避免选项被视口裁掉。用预设问题所在区域关闭菜单的那次点击只关闭菜单，再点一次即可填入问题。

提问框的霓虹亮度用渐变叠层的透明度过渡。星形标志沿原轮廓的长度分配循环色带，中心圆单独呼吸。局部 Canvas 绘制独立漂移、渐亮、停留和淡出的光点，尺寸按工作台的标志调整。系统启用减少动态效果时，菜单和高亮即时切换，标志保持静态。切到后台后暂停更新描边和粒子。

## 设置弹窗与页签过渡

设置弹窗在退场结束前保留原生模态行为，关闭后再归还焦点或从 `/settings` 返回工作台。两处页签各移动同一个选框，内容和键盘选中状态随选择立即更新。系统启用减少动态效果时跳过这些过渡。

弹窗进场先显现内容，再让位移和缩放缓缓停稳。退场缩短并向终点加速，减少关闭设置后等待工作台重新可用的时间。页签选框在屏幕内连续移动，使用同一条曲线保持两处操作手感一致。[Atlassian Motion](https://atlassian.design/foundations/motion/applying-motion) · [GitHub Primer Dialog](https://primer.style/view-components/lookbook/inspect/primer/alpha/dialog/playground/) · [IBM Carbon Motion](https://www.carbondesignsystem.com/building-blocks/foundations/motion/overview)

设置表单直接接受模型 ID。新提问使用工作流按节点和研究深度分配的默认思考强度，已有任务的重试沿用原有快照。

## 终稿结构与证据不足

Dispatcher 和背景调查的结构化回复仍使用 `json_repair` 尝试恢复正常结束的 JSON 语法错误，再做严格类型检查。修复前后必须保留标量内容和顺序。计划和审查使用独立的调度元数据，初稿和终稿直接使用 Markdown。

审查请求成功但控制块无法解析时，带格式提示重新请求一次。持续无效的输出和模型服务失败分别记录，均保留尚未完成审查的缺口。控制块仍按原字段和类型校验。

报告结构由模型按问题和证据决定。终稿引用可选，以保留综合分析与模型判断，代码验证显式引用的证据 ID 和来源范围。终稿缺少可保留正文时，按时间倒序重新核对已生成的草稿，交付最近一份有可用引用的草稿及状态说明。

降级开始时借助已有研究事件通知工作区。模型适配层识别服务和输出错误，通知提供固定中文原因和可尝试的处理方法。顶部通知采用设置弹窗的缓动参数，关闭动作只影响通知，工作区可继续交互。事件可在任务结束后续读，避免快速完成时漏掉提示。新报告只保存草稿或证据缺口。工作区在显示时隐藏旧报告中可识别的降级提示。

终稿沿用首轮研究方向来选择报告写法。某一轮切换渠道是为了补证，若用最后一轮的来源决定文体，论文综述可能因最后补查官网而变成网页调查。缺口采用最近一次累计审查的判断；把每轮缺口合并会将已补齐的问题误列为局限。

正文编号在引用验证后分配，避免模型自行编号导致多轮证据或页码错配。新报告按论文或网页归并引用，已有元数据用于生成参考文献，证据表仍保留每个片段。匹配到既有内嵌来源格式的历史报告在读取时转换，历史数据库无需迁移。初稿继续核对数值，终稿的有效证据 ID 只能证明来源可追溯。

## 网页检索与正文读取

搜索候选和直读网页是独立步骤。Tavily 的部分请求曾在 Windows 本机代理连接阶段失败，直接使用同一密钥访问可返回结果。当前仅对本机回环代理的连接失败尝试一次直连，服务响应后的错误直接返回。这既保留了常用代理路径，也避免在可能已计费的请求之后自动重发。网页正文仍需要通过每次连接和跳转的公网地址与证书检查。

读下一段网页会重新抓取，再按偏移截取。重复偏移会跳过，本轮预算也限制续读。网页缓存和提取结果复用需要先解决原文变更、缓存失效及定位一致性，当前尚未实现。

## 验收边界

隔离脚本通过实际 API 和 worker 验证任务闭环，模型与搜索可由本地模拟服务提供。浏览器 fixture 验证界面和交互，真实服务验收验证协议、权限、限流和质量。维护时按改动分别验证这三层，具体结果随对应提交或评审记录保留。
