# 持久化模块约定

- `storage.py` 管理数据目录、SQLite 连接、表结构初始化与升级。默认 `data/` 和相对 `TUFA_DATA_DIR` 均以仓库根目录为基准，不因模块层级变化而改变。
- `repository.py` 管理项目、文献、任务、消息、报告和收藏夹的持久化及事务，供 API 与 worker 复用，不负责联网、PDF 解析或模型调用。
- 每个连接启用外键与 WAL。写入使用短事务，耗时业务在事务外执行。
- 结构升级兼容已有数据库且可重复执行；不能删除数据库或重建用户数据绕开升级。
- DOI/arXiv ID 标识文献，文件版本保留原文定位；区分项目关联与全局共享文献，删除关联不得连带删除其他项目依赖的数据。
- 任务输入与收藏夹论文快照用于复现和重试，不在执行时用收藏夹当前成员覆盖快照。
- chat task 的 `research_mode` 使用可加列迁移，历史行默认 `auto`；创建与 retry 均需保留该模式，不能覆盖原任务值。
- 科研问答的报告、回答消息、证据与成功状态在同一事务内提交，避免成功任务缺失结果。

验证数据保留、项目隔离、快照、任务状态和事务可观察结果，使用临时数据库，入口见 [测试规则](../../tests/AGENTS.md)。
